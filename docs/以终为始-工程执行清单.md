# 《以终为始的工程执行清单》

> 来源：`推理成本优化.md`（领域自适应投机采样推理系统）
> 定位：个人施工蓝图 · 从零真实开发 · 粗粒度 · 不排期
> 原则：从最终交付物反推执行步骤；本文与简历稿中的所有量化指标均为**设计目标**，非实测结论，实测值以 `P0-baseline.md` 与 P5 报告为准

**全局硬前提：**
- 云 GPU：RTX4090 24G 单卡（AutoDL，租用；中途不换平台）；项目总卡时 ≤200 小时（天花板，工作假设 80-120）
- 目标模型 `Qwen3-8B`；草稿池 `Qwen3-0.6B` / `Qwen3-1.7B`（同族同词表 151936；4B 草稿已排除：8B+4B fp16 权重 22.75GiB，4090 24G 下 KV cache 所剩无几）
- 数据集：ALCE（RAG 引用型）/ RepoBench（代码）/ 自建中文结构化抽取协议（DuReader 篇章）；HumanEval 降为正确性验证
- vLLM `0.29.0` 为基线版本，锁定 commit + 镜像 digest
- 参考指标（目标，非硬验收）：TPOT −57%、吞吐 2.3×、接受率 +31%、单位成本 −45%、prompt-lookup 复制命中 ~82%

## P0 · 立项与基线

**终点目标：** 问题与基线锁定，前提盘点完成。

- 命题：固定草稿跨领域加速不稳定（长度无关）；复制型长上下文场景可由零成本草稿捕获（长度相关）
- 输入协议：中文 / 代码用原生长度，RAG 保留 4-8K 合成长档
- 输出协议：加长输出（答案 + 理由 + 引用），自然停止 / 固定 512 两档
- 三档基线（plain / fixed-draft / ngram），主对比轴 B1
- 瓶颈复现实验（TTFT vs TPOT）
- smoke 三条门槛 + ≤3 天时限 + go/no-go
- 交付：协议文档、基线结果 JSON、实测标定的预算表 v2

## P1 · 基建

**终点目标：** 本地 + 云开发环境与协作规范可用。

- 云 GPU 与远程开发链路（SSH / 镜像 / 数据盘 50G，暂不扩容，磁盘纪律见 `docs/P1-基建.md`）
- git / GitHub 仓库；`AGENTS.md` 与约束框架（代码规范、提交规范、协作边界）
- 数据获取链路：`HF_ENDPOINT=https://hf-mirror.com` 主源 + ModelScope 手动应急预案
- 协作模式：git 单向（本地唯一写入口，云端只 pull）；训练/评测产物 scp 回传本地归档

## P2 · 领域路由与草稿池

**终点目标：** 多草稿池 + 两级路由器在基线 vLLM 上跑通。

- 同族草稿池加载验证（词表一致性实测）
- 「关键词 + FastText」两级请求级路由器（开销 <5ms）+ 会话级粘性绑定 + 滑动窗口接受率监测与自动降级兜底
- 路由器训练样本与评测样本零重叠

## P3 · 引擎集成（不 fork）

**终点目标：** 单引擎内多草稿共存与请求级切换跑通。

- 走官方扩展点 `speculative_config.method="custom_class"`，不维护引擎分支
- 薄 patch：多草稿注册表 + 每请求草稿绑定
- 多草稿显存路线（探针决定）：(b) 1.7B 基座 + LoRA 草稿头；(a) 0.6B+1.7B 常驻
- 记录草稿换入换出与 CUDA graph / prefix cache 的冲突，以及切换期延迟尖刺

## P4 · RAG 专项加速

**终点目标：** 专项加速策略生效。

- prompt-lookup：对照并调优上游 ngram 实现，在 ALCE 扩长档上评估复制命中率
- 中文结构化抽取场景的复制率评估
- LoRA 微调草稿模型（CodeAlpaca + C-Eval 混合语料 ≈1.7M token，规模偏薄，需评估是否扩语料）
- 动态投机长度：对照上游 `num_speculative_tokens_per_batch_size` / `enable_adaptive_verification`，只做策略差异部分

## P5 · 评测与无损验证

**终点目标：** 统一评测口径 + 无损性证明 + 边界界定。

- 统一评测：只用 vLLM 原生指标（SpecDecodingStats + latency/throughput）
- 采样口径下的逐 token 输出分布一致性比对
- 边界：BS ≤ 8 最优区间、高并发衰减规律
- 消融：同词表 vs 跨词表映射（`vocab_mapping`）
- 在线并发压测（与离线 batch 数字分开报）

## P6 · 开源发布

**终点目标：** 可复现的公开仓库。

- 代码、评测脚本、复现文档、README 结果表
- 许可合规：C-Eval（NC+SA）、RepoBench（NC+ND）标注清楚
- `docs/` 规划文档不入库；结论文档是否发布净化版届时决定

## P7 · 收尾复盘

**终点目标：** 目标对照与总结。

- 对照参考指标逐项核对，标注达标 / 未达
- 工程可行性与局限性总结
