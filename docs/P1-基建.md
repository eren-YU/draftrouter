# P1 · 基建 — 边界定义与协作模式

> 本文档是 P1 阶段的验收凭证与长期有效的边界约定。AGENTS.md 管"怎么做"的操作规则,本文管"谁在哪、什么走什么通道"的边界。冲突时以本文为准并回写 AGENTS.md。

## 1. 本地 / 云端职责边界

| | 本地(D:\code\draftrouter) | 云端(AutoDL,`ssh autodl`) |
|---|---|---|
| 职责 | 编辑、纯逻辑单测(mock GPU)、review、commit、归档 | 算力执行:微调、评测、大规模生成、GPU 冒烟 |
| 事实源 | **代码唯一事实源**(git) | 只读代码:`git pull`,**禁止在云端 `git commit`** |
| 环境 | 无 GPU 依赖,测试不 import vllm | conda `draftrouter` 环境,vLLM 0.29 + torch 2.13 |

## 2. 同步通道:代码走 git,产物走 scp

- **代码**:单向 `本地 commit/push → 云端 git pull`。云端产生的任何代码级修改一律视为临时调试,确认有效后由本地落盘再 commit。scp **不**作为代码的常规通道(仅单文件应急,且事后必须回写本地)。**云端 pull 前脏改动细则**:云端 tracked 文件被调试改动会导致 pull 被拒——三选一:改动有价值 → scp 回写本地再 pull;无价值 → `git checkout -- <file>`/`git stash` 丢弃;禁用 `git pull -f` 与云端 commit。
- **产物(checkpoint / 评测输出 / 指标)**:不进 git(.gitignore 已排除权重)。云端 → 本地走 `scp`/`rsync` 拉回归档,拉回确认后云端可删。

## 3. 中间产物回传策略(训练 / 评测长任务)

1. **定期回传**:训练每产出一个 checkpoint 即 `scp` 回本地归档,本地目录约定 `D:\code\draftrouter-artifacts\<run-name>\`;评测原始输出跑完压缩后拉回。
2. **一致性保障**:云端 checkpoint 落盘后先 `sha256` 校验,再传输,传输完成本地校验一致后才允许删云端副本;禁止在训练进程写 checkpoint 的同时拉取。
3. **执行主体**:回传不是事后手动动作——启动长任务时必须附带回传手段,二选一:(a) 云端 `watch` 脚本监控 checkpoint 目录,稳定即自动 scp;(b) 训练脚本收尾回调内联 scp。禁止依赖"跑完后想起来"。
4. **云端保留最近 1–2 个 checkpoint** 供断点续训;更早的回传确认后删除。
5. **中断恢复**:云端 checkpoint 在 → 直接续;已被清 → 从本地回传(Qwen3-0.6B 全量 checkpoint ≈ 1.4G,分钟级)后续。
6. **本地是归档层**(D: 盘 278G 空闲,余量充足),云端数据盘是工作层。**已知风险:归档层是单副本**,依赖 D: 盘可靠性;P1 收尾 commit 必须伴随一次 push(GitHub 作代码层第二副本),artifacts 是否双备份延后决策但记录在案。

## 4. 磁盘纪律(云端数据盘 50G,暂不扩容)

现状(2026-09-15):已用 35G(hf-cache 34G:Qwen3-0.6B/1.7B/4B/8B 全部就位;数据集约 1G),剩 16G。

- 模型规划已锁定(target Qwen3-8B,草稿 0.6B/1.7B),**不再有同级大下载**。
- **Qwen3-4B 草稿路线不可行**:8B fp16 15.26GiB + 4B fp16 7.49GiB = 22.75GiB,4090 24G 在 `gpu_memory_utilization=0.95`(≈22.8GiB)下 KV cache 仅剩约 0.05GiB,spec-decode 无法运行。hf-cache 中 7.6G 的 4B 缓存为死重,可删。删后余量 23.6G。
- 新增下载前先 `du -sh` 评估;模型规划若变更必须重新评估扩容。
- checkpoint 只留最优与最近,不放中间 epoch;生成结果压缩归档后云端即删。
- 磁盘 >80%(40G)时触发清理:先清临时产物,再评估删已回传的 checkpoint。

## 5. 数据获取链路:hf-mirror 主源 + ModelScope 手动预案

- 主源:`HF_ENDPOINT=https://hf-mirror.com`,直链清单见 `scripts/data_prep/download_data.py` 的 `DOWNLOAD_PLAN`(各 URL 均为云端实测 200)。
- **ModelScope 为手动应急预案,不做代码级自动 fallback**:hf-mirror 全线失效时,在 ModelScope 搜同名数据集/模型手动下载。**注意 ModelScope 缓存布局与 HF hub 不同**,不可直接塞进 `hf-cache`:权重类下载原始文件后手工重建 `models--<org>--<name>/snapshots/<rev>/` 结构,或放任意目录后以本地 path 加载(`HF_HUB_OFFLINE=0`);数据类直接放 `/root/autodl-tmp/data` 后重跑构建脚本。
- 网络规则不变:pip 不开加速;git/HF 下载先 `source /etc/network_turbo`;读缓存用 `HF_HUB_OFFLINE=1`。

- 提交规范见 AGENTS.md「提交规范」一节:Conventional Commits,commit 前 `ruff check`(不引 pre-commit)。
